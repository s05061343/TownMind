# ADR-0001：以標準化 ROI 作為第一階段動態座標

- **狀態：** Accepted
- **日期：** 2026-08-09

## 背景

目前只有一組已確認的 AOE2 DE 畫面：2560×1440、全螢幕、繁中 UI、HUD 50%。需求希望 ROI 能動態對應畫面尺寸，但尚未有其他 HUD Scale 與解析度樣本可驗證圖示定位。

## 決策

- Profile 使用 0～1 的標準化矩形保存 ROI。
- 執行時依輸入畫面的實際寬高換算為像素座標。
- Profile 同時保存校正解析度、語言、HUD Scale 與顯示模式。
- `IAnchorCalibrator` 保留為後續擴充介面。
- Profile 與實際 HUD 配置不相容或 Anchor 校正失敗時，系統必須停止輸出觀察值。

## 理由

- 可立即避免把 2560×1440 像素座標散落在程式碼中。
- 相同 HUD 佈局下可處理等比例畫面變化。
- 不會在缺乏測試證據時宣稱已解決任意 HUD Scale。
- 未來可在不改變下游 Observation 契約的情況下加入 Anchor 校正。

## 限制

- 不保證不同 HUD Scale、語言或重新排版後仍正確。
- 寬高比不同時，分別縮放可能造成 HUD ROI 偏移，因此需要 Profile 相容性檢查或 Anchor 校正。
- 每個新增支援環境都需要截圖回歸測試與 ground truth。
